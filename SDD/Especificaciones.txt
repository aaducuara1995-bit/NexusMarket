El Modelo de Dominio de NexusMarket representa los elementos y procesos de negocio de una plataforma Marketplace, tomando como base la especificación funcional del sistema.

Para su construcción se aplican conceptos de Programación Orientada a Objetos y principios de Diseño Dirigido por el Dominio (DDD). El dominio está escrito en Java y no depende de bases de datos ni de interfaces gráficas: solo contiene las reglas del negocio.

El modelo contempla principalmente:

•	Usuarios, las personas que interactúan con el sistema, cada una con un único rol: Comprador, Vendedor, Operador Logístico, Administrador o Supervisor.
•	Compradores, los usuarios que realizan compras, con sus direcciones de entrega y su estado comercial.
•	Vendedores, quienes comercializan los productos. Los incorpora un administrador.
•	Productos, los artículos físicos o digitales del catálogo, cada uno de un vendedor.
•	Bodegas e Inventario, el almacenamiento y las existencias de los productos, con reservas y registro de movimientos.
•	Carritos y Pedidos, el proceso de selección, confirmación y pago de una compra.
•	Facturas y Envíos, la información económica de la venta y la entrega de los productos físicos.
•	Devoluciones y Reembolsos, los procesos posteriores a una compra.

El dominio se organiza en las siguientes partes:

•	Entidades, los objetos del negocio con identidad propia (ver entidades.txt).
•	Objetos de valor, los datos que se validan por sí mismos (ver objetos_de_valor.txt).
•	Enumeraciones, los estados y tipos del negocio, como el estado de un pedido o el rol de un usuario.
•	Excepciones, los errores propios del dominio, como el acceso denegado cuando un rol intenta una operación que no le corresponde.
•	Servicios de dominio, las reglas que involucran a varias entidades a la vez, por ejemplo repartir la reserva de un pedido entre varias bodegas o despachar un pedido actualizando el envío, el pedido y el inventario. Aquí se aplica también la matriz de responsabilidades de la especificación funcional.
•	Puertos de salida, las interfaces con las que el dominio consulta información externa, por ejemplo si un correo ya está registrado, sin depender de una base de datos concreta.
•	Puertos de entrada, los casos de uso que el sistema ofrece hacia afuera, como registrar un usuario o pagar un pedido.

De esta manera, el Modelo de Dominio sirve como base organizada para el desarrollo de NexusMarket y lleva al código las necesidades y reglas de negocio identificadas en la especificación funcional.
